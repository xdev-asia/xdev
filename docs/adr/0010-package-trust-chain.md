# 0010. Packs and the registry index are signed with ed25519, keys can rotate

Status: proposed.
Date: 2026-11-02

## Context

ADR 0001 says a pack (`.xpkg`) is signed with ed25519 and the registry is a
signed static `index.json` with a block list. It does not say who holds
which key, how a key is replaced, or how the app knows an index is current.
The pack carries the manifest of ADR 0009, so its signature is what makes
the capability list trustworthy.

## Decision

- A pack is a zip: `manifest.json`, `plugin.wasm` (optional), `ui/`
  (optional), `files.json` and `signature`.
  - `files.json` lists every other file with its SHA-256.
  - `signature` is the publisher's ed25519 signature over `files.json`.
  - The app checks the signature, then every hash, before it reads the
    manifest. Any mismatch, extra file or missing file: not loaded.
- Keys are separate by job. A publisher key signs packs. The registry key
  signs the index. The app's update key (a separate ADR) signs app updates.
  No key does two jobs.
- Publisher keys: one per publisher, generated by the publisher. The
  manifest's `publisher` field is the key id (a hash of the public key).
- Registry: a Git repository. A publisher adds a version by pull request;
  CI checks the manifest schema, capabilities and signature. On merge, CI
  writes `index.json`: for each pack, id, version, publisher key id, pack
  URL and SHA-256.
- `index.json` has a `serial` that only goes up and an `expires` time. It is
  signed by the registry key in `index.json.sig`. The app rejects an index
  with a bad signature, a lower serial than the last one it saw, or a past
  `expires`. A stale index means no new installs, not that installed apps
  stop.
- The app ships with the registry's public keys. The index may name a next
  key, signed by the current one; the app accepts it, then trusts only the
  new key once an index signed by it arrives.
- Publisher key rotation: the publisher signs the new key id with the old
  key and submits it by pull request. The index records both until the old
  one is retired. A lost publisher key needs a manual review in the
  registry repo.
- Block list: in `index.json`, by pack id and version, or by publisher key
  id. The app turns off a blocked pack on the next index fetch and tells the
  person why. A blocked publisher key blocks all its packs.
- A compromised registry key is replaced by an app update signed with the
  update key; this is the only path, so the update key must be kept apart.

## Consequences

- Every installed pack can be traced to a publisher key and an index entry.
- Rollback of the index to an old, unblocked copy is caught by `serial`.
- The registry costs nothing to host: a Git repository and static files.
- Publishers must keep a key safe; losing it means a manual recovery.

## Open questions

- Sigstore (keyless signing tied to an identity) and SLSA provenance could
  sit on top of ed25519 later. [Unverified] Not evaluated yet.
- Whether an unsigned pack may be loaded from a local folder in a developer
  mode, and how that is shown to the person.
- Where the registry private key is held and who may sign with it.
